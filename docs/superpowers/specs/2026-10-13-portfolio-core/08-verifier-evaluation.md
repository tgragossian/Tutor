# 08 — Verifier evaluation

[Contracts index](README.md) · [Evaluation review](../../../reviews/2026-10-13/evaluation.md)

## Datasets (`evals/verifier/`)

| Set | Source | Purpose |
|---|---|---|
| `human/dev.jsonl` | Written by hand **and reviewed**, each case with a rationale | Development and regression |
| `human/final.jsonl` | Same process, split off **by problem family** | Frozen release measurement |
| `generated/*.jsonl` | Rewrites and mutations generated by SymPy | Regression only; reported separately and **never** cited as accuracy |

- **Inputs are real browser captures.** Each case's MathJSON comes from the capture tool driving MathLive, not from a SymPy serializer. Raw inputs are kept alongside.
- **Case record:** `{id, family, problem_id | inline_spec, answer: <payload>, label: correct|incorrect|unsupported, rationale, reviewer}`.
- **Splits** are made by `family` (one source problem and all its variants) **before** any variants are generated. A family never appears in both dev and final.
- **The final set is frozen:** its file hash is recorded in `evals/verifier/FROZEN.md`. Each run against it is logged with the verifier version. Tuning rules after seeing final results requires a new final set, and the exposure is recorded.
- **Wrong labels** are corrected only with a written rationale in the case history. Silently relabelling a case to make a test pass is never allowed.
- **Coverage per answer kind:**
  - correct-but-tricky forms
  - typical errors
  - domain traps (holes, poles, log and √ domains)
  - near-equal perturbations
  - partial or placeholder input
  - unsupported notation
  - resource limits
  - decimals at rounding boundaries

## Metrics (all with denominators)

- **FA** = wrong inputs accepted ÷ wrong inputs.
- **FR** = correct inputs judged incorrect ÷ correct inputs.
- **Abstention:** reported separately for correct, wrong and unsupported inputs.
- **Supported coverage** = correct inputs judged correct ÷ correct inputs.
- **Uncertainty:** each rate is reported with a 95% Wilson interval. A rate of 0/n is reported as "0 of n (95% upper bound ≈ 3/n)", never as "0% error".
- Results are broken down by kind × reason × method.
- **Latency:** worker and queue p50/p95 on a **named host and workload**. Reported, not gated.

## Release gates

| Gate | Milestone B demo | Milestone E release |
|---|---|---|
| Human cases total | ≥ 80 dev | ≥ 300 across dev + final |
| FA (human, any set) | 0 observed | 0 observed |
| FR (human) | ≤ 2% | ≤ 2% |
| Supported coverage (human correct inputs) | ≥ 85% | ≥ 90% |
| Generated-set FA | 0 observed (regression) | 0 observed (regression) |

- **CI runs on `dev` and `generated` on every push** and enforces all the gates in the current column.
- **`final` is run only for releases.** The command and output are committed as `evals/verifier/results/<version>.json` plus a short Markdown summary.
- **A verifier that abstains on everything fails the coverage gate.** Abstention is never a way to pass.
