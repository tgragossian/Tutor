# 02 — Answer contracts

[Contracts index](README.md)

## MathLive and Compute Engine

- Pin **MathLive 0.111.1** or later, which includes the 0.111.1 fixes for script-injection (XSS) bugs.
- Pin a compatible `@cortex-js/compute-engine`. The milestone A spike records the exact version in ADR 0002.
- `getValue('math-json')` was removed in 0.111.0. Instead use `MathfieldElement.computeEngine.parse(mf.getValue(), {canonical: false}).json`. ADR 0002 confirms the supported non-canonical option name.
- The browser sends **MathJSON for grading** and **LaTeX for display and logging only**. LaTeX is never graded.
- Vendor files are self-hosted under `static/vendor/` with SRI hashes. There are no CDN calls at runtime.

## Submission payload (one discriminated union)

```json
{"submission_id": "<uuid4, generated by the client>",
 "session_item_id": 42, "item_revision": 3,
 "answer": {"kind": "expression", "mathjson": <tree>, "latex": "6x\\cos(3x^2)"}}
```

- `answer.kind` ∈ `expression | numeric | choice` and must equal the item's kind; otherwise the server returns 422.
- `choice` sends `{"kind": "choice", "choice_id": "b"}` with no MathJSON. Choice submissions are dispatched **before** any expression pre-check, which fixes the review's empty-LaTeX bug.
- Request body ≤ 16 KB. Bounds on the tree itself are in [03](03-input-bounds.md).

## Pre-checks (a format issue: no attempt recorded, no retry consumed)

| Condition | Code |
|---|---|
| Empty tree, or `Nothing` | `empty` |
| Placeholder or `Error` node anywhere | `incomplete` |
| Decimal answer where `precision: exact` | `exact_required` |
| Decimal with fewer than N places | `too_few_decimals` |

## Decimal precision

- Decimal places come **only** from the MathJSON number token, as its literal digit string.
- The spike records how Compute Engine encodes a decimal such as `0.780`, keeping its trailing zero (for example `{"num": "0.780"}`).
- If trailing zeros cannot be preserved, the milestone A fallback is to **not** enforce a minimum number of places. Any decimal is then graded by rounding to N places, and ADR 0002 records the change.
- A decimal anywhere other than as the top-level value of a `numeric` answer (inside a fraction, say) is graded symbolically as an exact rational.
- **Rounding rule:** compute exactly with `decimal.Decimal` from the rational expected value, using ROUND_HALF_EVEN. The student's decimal is correct iff `round(expected, N) == round(student, N)` at N = `decimals`.
- An **exact** student answer to a `numeric` problem is checked symbolically ([04](04-equivalence.md)).

## Deferred kinds (contracts fixed now, implemented with topic expansion)

- **`antiderivative`:** the content stores the **integrand** and its real domain.
  - The student may include `C`, a symbol allowed only for this kind.
  - Correct iff d/dx(student) is proven equal to the integrand on the domain ([04](04-equivalence.md)) **and** the student's expression does not depend on `C` in any way except an additive `+C`.
  - Whether `+C` is required is set per problem by `require_constant` (default `false`). A missing required constant is a format issue (`constant_required`), not a wrong answer.
- **`limit`:** tokens `oo`, `-oo`, `DNE`, or an exact value.
- **`point_set`:** a finite set; each element is checked with the `numeric` rule; matching is one-to-one via bipartite assignment, so it never depends on the order elements are listed.
- **`implicit_derivative`:** the exact polynomial reduction contract in decision 0001.
- **Abstract functions:** for recall items such as the product rule, `f(x)` is allowed only with the bare variable as its argument. `f(2x)` is `unsupported_notation`, not silently the same symbol.

## Public vs. private fields

- Item DTOs never contain `answer.latex`, `correct`, `misconceptions` or `review`.
- The expected answer leaves the server only through the reveal endpoint ([06](06-session-state.md)).
