### Task 13: Buttons, panel, citations and the browser test

**Files:** Modify `src/mathtutor/web/static/practice.js`, `web/templates/practice.html`,
`web/static/app.css`, `tools/e2e/smoke.mjs`, `tests/container/smoke.sh` (run the container with
`MATHTUTOR_HELP_GENERATOR=scripted`); Create `tools/web/help_panel.test.mjs`.

**Interfaces:** Consumes `PublicItem.help` and `POST /api/help` (Task 12). The scripted
generator in `env=test` containers returns one fixed cited hint for any request so e2e is offline.
The container keeps `MATHTUTOR_ENV=production` elsewhere; e2e uses a separate compose override
with `env=test`, never the deployed configuration.

UI rules:
- Render buttons only when `help` is non-null: **Hint**, **What did I do wrong?** (only when the
  latest outcome is a wrong answer), **Explain this** (opens a select of `help.confusions`).
- Each click creates a `crypto.randomUUID()` request ID; the button disables until a terminal
  status; `PENDING` polls once after 2 s with the same ID.
- Show `html` (server-rendered, safe) in `#help-panel`, then each source as
  `OpenStax Calculus Vol. 1, {label} ↗ · CC BY-NC-SA 4.0` with the server URL (`rel="noopener"`).
- Ignore a response whose `session_item_id`/`item_revision`/`help_seq` is older than the current
  view; clear the panel when the item changes, is answered correctly, revealed or advanced.
- `LIMITED`/`UNAVAILABLE`/`ABSTAINED` show their fixed message text from the response; never raw errors.
- Text below the panel: "Help is written by an AI model using the textbook and is designed not to
  give away the final answer; use Reveal for that." No "never leaks" claim (spec 03). Thomas approves wording.
