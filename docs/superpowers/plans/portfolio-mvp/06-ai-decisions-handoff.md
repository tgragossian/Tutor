## Decided

1. **Order:** milestone C (RAG hints) → LoRA experiment → D/E → expansion queue (0005 §6).
2. **RAG source:** OpenStax *Calculus Volume 1* text may be chunked, indexed and sent to a hosted
   LLM under CC BY-NC-SA 4.0 and the "teaching and learning" guidance. The book's AI sentence is a
   recorded risk. Every hint cites its section with a link and the licence (0004 §1).
3. **Retrieval:** BM25 baseline first; dense/hybrid only if it beats BM25 on measured Recall@k/MRR.
4. **Hosted generator:** GPT-5.2 is the baseline; candidates Claude Opus 5.5, Sonnet 5.5, Haiku 5.5.
   The winner is the cheapest model non-inferior to the best. **Muse Spark dropped** (0004 §2).
5. **Evaluation targets hint behaviour, not math:** answer leakage per hint level, error-specific
   hints, not endorsing wrong reasoning, citation support; Wilson intervals; hard cases (0004 §3).
   Correctness is always the SymPy verifier's call, never an LLM's.
6. **Help type chosen by buttons** (no classifier): "What did I do wrong?" → feedback on work;
   **Hint** → active-learning hint (ladder: concept reminder → next step → fuller explanation);
   **Explain this** + short confusion list → adaptive explanation. The server adds the problem,
   attempts, tries used and any matched recorded misconception (SymPy-checked) (0005 §5).
7. **Answer-leak guard:** a deterministic SymPy check blocks hint text containing an expression
   equivalent to the answer (below the reveal level), logged as a leak event.
8. **Datasets:** TutorBench non-calculus = train; TutorBench Calculus (258) = eval only; Eedi and
   MathDial = train; TutorMoments and milestone C cases = eval only. Contamination check before
   every training job. No TutorBench rows, weights or generated sets in git or the image (0005 §1–2, §4).
9. **Fine-tune:** Qwen3.5-9B (Apache 2.0), QLoRA, one adapter for all three help types. Training
   responses are generated by Qwen and scored against TutorBench rubrics. OpenAI fine-tuning is
   closed to new orgs, so no GPT model is tuned (0005 §3).
10. **Comparisons:** A/B 1 = base vs LoRA (the experiment, offline, paired, the headline result);
    A/B 2 = LoRA vs the hosted C winner, on quality and cost per hint.
11. **Training compute:** AWS `g5.xlarge` (A10G 24 GB), spot when possible, stopped after each run;
    request the GPU vCPU quota early; raise the $10 budget alert (it is not a cap).
12. **Serving:** RunPod Serverless, one 24 GB worker running vLLM with base + adapter (both A/B arms),
    scale to zero, max workers 1. Fireworks/Together rejected: no per-token LoRA serving (0005 §6).
13. **Live A/B:** each student keeps one arm (base or LoRA) from sign-up; arm logged on every hint.
    Live measures: SymPy result of the next attempt, leak rate, reveal rate, thumbs up/down.
    Descriptive only at ~50 students.
14. **Fallback:** LoRA/base on RunPod → hosted C model → "hints unavailable"; practice keeps
    working. Timeouts, per-user rate limits and a global usage budget before public launch.

## Sizing and cost notes (not yet in 0005; it is at 100 lines)

- Qwen3.5-9B: 9.65B params, 262K context; about 32 KB of KV cache per token (8 of 32 layers
  full-attention, 4 KV heads × 256). Weights: bf16 ≈ 19.3 GB, 8-bit ≈ 9.7 GB, 4-bit ≈ 5.5–6 GB.
- Serving needs Ampere or newer (vLLM); V100 and Thomas's GTX 1070 Ti are unsuitable.
- RunPod calculator (24 GB, 50 requests/day, 5 s each): $0.92/month execution only. Adding the
  idle tail and cold starts: **≈ $2/month** if FlashBoot (sub-200 ms, reuses a cached worker)
  mostly hits, **up to ≈ $5–8/month** if full cold starts (tens of seconds, loading weights) are common.
- Hosted generator spend for the C comparison: ≈ $5 total. AWS training: tens of dollars.
