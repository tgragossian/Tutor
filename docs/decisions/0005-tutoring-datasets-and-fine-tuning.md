## 2. TutorBench training (Thomas's decision)

- **Basis:** Thomas judges training a private, noncommercial portfolio model on TutorBench to be
  fair use. Recorded facts: the dataset card states no licence; the public sample is CC BY-NC
  4.0; the paper is CC BY-NC-ND 4.0, which licenses the paper, not the dataset.
- **Split:** all 258 Calculus tasks are held out for evaluation and never used in training,
  prompting examples or response selection. Training uses the other subjects, tagged by use case.
- **Method:** TutorBench has rubrics, not reference answers. Generate several responses per
  training task, score them against the task's rubric, and train on the best (or best-vs-worst
  pairs). Judge model, prompts and scores are versioned.
- **Weights are not published.** Adapters, checkpoints and generated training sets stay out of git
  (`.gitignore`: `models/`, `data/`, `*.safetensors`, `*.gguf`) and out of the Docker image. Only
  configs, task IDs, scores and the write-up are committed. No TutorBench rows enter the repo.
- **Credit:** the README credits TutorBench (Scale AI; Srinivasa et al., 2025) and notes the
  paper's CC BY-NC-ND 4.0 licence. Eedi and others are credited under their own licences.
- Revisit if Scale AI publishes a dataset licence or objects, or before any commercial use.

## 3. Model and comparisons (Thomas, 2026-10-22)

- **Base: [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B)** (Apache 2.0, 9.7B, 262K context), LoRA via
  PyTorch / Hugging Face. Not Qwen2.5-Math-7B: its card says it is for solving problems only, and
  its 4K context is too small for retrieval plus dialogue. Qwen3.8-27B is a possible follow-up.
- OpenAI fine-tuning is unavailable (closed to new organisations since 2026-05-07; GPT-4o and
  GPT-4.1 base models shut down 2027-01-14), so no GPT model is fine-tuned.
- **A/B 1 (the experiment):** Qwen3.5-9B base vs the same model + LoRA, with identical retrieval,
  prompts and decoding, on the held-out evaluation sets. Paired per case.
- **A/B 2 (the reference):** the LoRA model vs the hosted generator chosen in milestone C
  (decision 0004: GPT-5.2, Muse Spark, Claude models), on quality and cost per hint.
- **Hosted models are used without fine-tuning**, as C's generator candidates and as rubric
  judges. Training responses are generated by Qwen itself (scored by the judge), not by hosted
  models, so no provider's terms on using outputs to train other models are at issue.
- Serving the LoRA model needs a GPU host; the 1 GB web server cannot run it.

## 4. Rules that keep the evaluation meaningful

- Never train on evaluation data: TutorBench Calculus, TutorMoments, and the milestone C hint
  cases. A contamination check (task-ID and text overlap) runs before every training job.
- One adapter for all three use cases (use case in the prompt), compared against the hosted model
  selected in milestone C under fixed retrieval, prompts and decoding.
- Report rubric scores with uncertainty, per use case, plus cost per hint. A null result is a
  reported finding. OpenStax text is not used for training (decision 0004 §1).

## 5. Routing (decided) and timing (open)

- **Use-case routing (Thomas, 2026-10-22): buttons.** On the practice page the student picks the
  kind of help, so no classifier is needed: "What did I do wrong?" after a wrong answer →
  feedback on work; **Hint** → active-learning hint; **Explain this** (with a short list of
  confusion options) → adaptive explanation. The server adds the problem, attempts, tries used
  and any recorded misconception the wrong answer matches (checked with the SymPy verifier).
  A free-text question box comes later; the hint model then states the use case in the same
  call, with routing accuracy measured on TutorBench's use-case labels.
- **Timing (open):** move the fine-tuning experiment to directly after milestone C, or keep it last in
  the expansion queue.
